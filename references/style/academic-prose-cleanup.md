# 学术表达清理与语域保护

用于中文土木工程学位论文、英文论文及审稿修改的语言清理。它补充而不替代证据、引用、术语和 Word 编辑工作流；不新增主任务模式。语料范式优先采用作者认可的论文样本。外部规则来源及版本见 [来源台账](../meta/external-skill-sources.md)。

## 与反防御性写作的关系及优先级

| 层面 | 解决的问题 | 保留的内容 |
|---|---|---|
| 反防御性写作 | 中心贡献不明确、论证像工作日志、反复解释为何没做其他工作、无必要的自我贬低 | 有证据支持的贡献及完整的论证依据 |
| 学术表达清理 | 空泛套话、机械复句、翻译腔、抽象名词堆叠、虚构对立、指代不明 | 作者语气、专业语域、事实与原有逻辑关系 |
| 二者交集 | 多层重复保留语、空洞预告和复述、正文中的答辩式解释 | 表达真实不确定性的限定语及必要技术说明 |

发生冲突时，按以下顺序处理：事实与科学披露 > 已授权的编辑范围及控制模板 > 作者认可的专业语体 > 贡献组织 > 一般语言偏好。反防御性规则只针对冗余修辞，不能据此隐瞒实质性反证或必要条件；各工作流均应遵守这一区分，发现矛盾时修正源规则，不依靠新增例外掩盖。

- 影响结果解释的假设、失败工况、非单调趋势、重要对比劣势和适用条件，应在相关方法或结果位置简明交代，不必机械另设局限性章节。
- 无关的失败尝试、泛泛的“仍需进一步验证”以及对没人提出的质疑反复自辩，可留在研究记录或修改说明。
- 不新添泛化局限性段落；也不删掉已有且有科学意义的让步、限制与负面发现。删掉后会使结论误导读者的内容必须保留。

## 选择编辑强度

| 编辑强度 | 触发 | 允许变化 |
|---|---|---|
| 最小清理 | 只去套话、只去 AI 味、已经定稿、仅修语言 | 只改能定位的表达缺陷；其余文字不动；保留标题、段落顺序和数量、图表、引用及章节空行 |
| 常规润色 | 润色、压缩、改善衔接 | 可调整句内组织、拆分难读长句；不擅自调章、删段或扩充证据；实质性重组先列建议 |
| 新稿写作 | 依据材料撰写正文 | 在已有 draft 流程中应用本指南；只有用户材料与已核实来源能够进入正文 |

这些是原有 draft/revise/audit 操作内部的编辑强度，不是新的 manuscript mode。只要求审查时，返回问题及位置，不写回文件。用户明确要求重构时再采用结构修改流程。局部请求不扩大到整篇。

## 编辑前锁定

1. 明确所改段落、语言、文类及作者指定的权威版本。读取上下文与可用风格样本，不因文件旧就否定作者选择。
2. 将数字与正负号、单位、百分比和百分点、统计符号、公式、变量、引用标记/键、交叉引用、模型名及规范编号作为保护对象。保留它们与对象、指标、工况、比较基线的对应关系。
3. 锁定定义、假设、定理陈述、直接引文及审稿意见原话。发现疑误时另列核对项，不以润色名义静默修正。
4. 针对每处语言修改，能指出“哪里不清楚、冗余、失真或不合专业语体”。仅仅“听起来像 AI”不构成修改依据。

## 按缺陷处理，不按词表删改

### 具体论点替代空泛评价

检查“意义重大”“具有广泛前景”“全面验证”“开启新范式”“paves the way”等是否包含可核查内容。能从当前材料找到指标、基线与图表时，直接陈述该结果；找不到时只收窄已有主张，并在修改说明中列缺证。不得自行补数值、来源或工程承诺。

“显著”若指统计显著性，需保留原有检验、统计量及显著性水平；若指工程差异，应陈述已有量值和工程判据，不把数值差异改成统计结论。“robust”作为既定算法类别或经验证的性质可以保留。

### 实际逻辑替代装饰性对立

“不是……而是……”“not merely ... but ...”若是在区分真实研究假设、机理或已引用观点，可以保留。若只树立一个并不存在的反面，再赞扬本研究，则改为直接主张。不把每个递进、对比句都判为套话。

### 信息衔接替代机械节奏

连续几句若重复“随着……增加，……增大，说明……”的空壳，先判断是否只是参数分析需要可比结构。有独立工程信息的并列比较不删；仅重复结论时合并冗余表达。不得为句式多样性轮换“内叶板”“内层板”等已经锁定的对象名。

“这说明”“由此可见”之后若给出了新的、有依据的机理或推论，保留；若只是把上一句改成抽象赞语，删除复述。论文规定的“本章小结”、章节编号、变量清单、加载步骤和有内容的贡献列表不因 humanizer 规则删除。

### 清楚优先于压缩

读者应能辨认谁做了什么、比较谁、何种工况、哪个响应以及证据是什么。首先删重复预告和总结，再删冗余短语，不先砍掉比较条件、指标名或解释所需的技术细节。

“其”“该结果”“this”出现多个可能先行对象时恢复明确名词，但不为补足逻辑而编造原因。名词链、过多从句或叠加比较条件造成歧义时拆开；已有清楚的短句保留。不规定统一句长、长短句比例或所谓随机节奏。

### 主语、动作与证据来源相符

“图中给出”“结果表明”“曲线显示”是正常表达，不强行改成“我们”。若写成“图表决定了设计方案”或“模型认定锚固不会失效”，应核对谁作出判断、依据是什么，再用现有证据重写。方法被动语态、合理的第一人称及必要逻辑连接词不是缺陷。

### 保留科学意义上的谨慎

仅在数值已经直接报告且无需不确定推断时，才把多余的“可能降低了所报告误差”改成“降低了误差”。从趋势推测机理、从相关性作解释时仍需“可能”“提示”“与……一致”。可合并意义重复的保留语，但不能把“suggests”改成“proves”。

### 中文与英文各自自然

中文少用没有对象的“实现了……的提升”“开展了对于……的研究”；已有对象明确时直接写“提高……”“研究……”。英文检查冠词、搭配、名词化和从中文直译的长前置结构，不将专业词换成日常词。

不以逗号、分号、冒号或破折号的出现本身判定写作来源。优先处理冗余插语和难读结构；保留范围连接号、负号、复合术语及引文符号。模板和作者明确认可的标点规范优先，不套用上游个人的“零破折号”偏好。

### 定义充分的名称不动，空壳标签要核对

“保障机制”“可信闭环”“智能协同框架”等若未定义、未说明组成且仅用于包装一步计算，应改为材料已有的具体操作。没有操作依据时列核对项，不发明组成。混凝土损伤塑性模型、注意力机制、网格无关性分析等既定术语，以及作者已定义的模型名，保持原称。

## 土木工程场景的校准

下列示例均为编辑示意，不是语料原句或可直接使用的研究结论；只有材料确有相应证据时才能采用。

| 场景 | 应处理的问题 | 推荐表达方向 |
|---|---|---|
| PCSP | “协同效应极其优越”未指明指标 | 分清刚度组合度、承载力组合度和叶板相对滑移；使用材料已有的工况与响应 |
| 有限元验证 | “完全吻合，证明可用于所有墙板” | 分别报告已核实的曲线阶段、峰值误差及破坏位置；不把验证范围扩大到未研究构件 |
| 参数分析 | “该因素决定破坏机理”只有趋势依据 | 区分受控变量、响应趋势与机理解释；不把相关趋势升级为排他性因果 |
| 机器学习 | “模型更优”混合训练集与测试集结果 | 保持数据划分、指标定义、比较模型及计算成本的对应，不合并不同批次数据 |
| SHAP | “证明拉结件间距导致承载力下降” | 表述为特征对当前模型预测的贡献；与独立力学证据分开 |
| 辅助设计 | “保证工程安全”只有 GUI 或代理模型结果 | 写明已实现的输入、预测、计算或方案筛选功能，不把功能演示提升为规范合规证明 |

例一：原句“值得注意的是，图中结果充分证明了模型的卓越性能。”若图中实际给出峰值荷载比较，可改成“图中给出了计算峰值荷载与试验值的对比。”仅有对比图不能自动得出精度结论；已有误差时才报告误差。

例二：原句“结果可能潜在地表明叶板滑移可能与连接刚度有关。”若证据仍为间接关联，可改成“结果提示叶板滑移可能与连接刚度有关。”不补写尚未检验的传力因果链。

例三：原句“本文只是初步尝试，尚不能保证普遍适用。”改写前先核对：若只是自贬，可删除；若原句唯一表达了样本范围，则将该范围明确纳入结果陈述。不能连同真实边界一起删除。

## 两轮核对与交付

第一轮核对表达：逐处诊断，做范围内最小充分修改；检查段落主张、已知到新信息的衔接，以及方法、结果、结论是否仍互相对应。缺证问题默认放在正文外的修改说明；仅在用户接受的草稿中使用醒目占位，并明确它不能直接提交。

第二轮核对不变量：对照原文检查受保护内容。既要比较字面值，也要核查谁对应哪个数、哪条引文支撑哪句话、条件是否被删。尤其检查不等号方向、负号、范围端点、百分点、样本来源及测试集标签；词频或 token 相同不等于语义相同。

- 小段落可人工逐项对照，并明确核对范围；多节、数字密集或正式文件修改应列出核对项目及发现的差异，必要时用可用的文本/结构 diff 工具辅助。
- 未执行检查时不能声称“全部不变量通过”；文本对照也不等于原始试验数据核验。Word 公式、域及版式仍走原有 OOXML/渲染检查，不以纯文本结果替代。
- 有意修正的数据、术语或引用仅在另获相应授权后进行，并逐项报告，不混入无差别润色。
- 按原有输出合同交付修改稿和简短说明，报告必要的主张收窄、真实限定语变更、缺证及未核查项。最小清理未命中的句子保持不动。

不承诺检测分数，不据语言特征判定作者身份，不制造错字、随机句长、口语化或虚假个人经历。遵守学校/期刊对 AI 辅助使用的披露要求；语言清理不能删除这些声明。

## 有意不迁移的上游规则

不迁移医学对象及临床结论、特定作者句长和连接词清单、强制随机节奏、统一改写比例阈值、自动删除本章小结、强制另建局限性段落、全面禁用特定标点或学术词，以及删掉工程复现参数的泛化要求。未复制或运行上游脚本，也不把上游自述的测试效果当作本 skill 的验证结果。
