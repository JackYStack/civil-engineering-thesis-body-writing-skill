# 文献讨论中的翻译保真与解释溯源

在讨论正文、核查引用、解释文献或比较研究时，只要将外文来源译给用户或据此提出中文解释，就应用本指南。不要求用户另外点名翻译，也不默认生成整篇双语阅读稿。它补充现有引用支持分级与PDF抽取核对，不新增主模式。

## 范围和优先级

- 局部讨论：围绕用户当前问题，读取相关原段落及必要上下文；按需核对所依赖的图、表、公式、图注或表注。只翻译所需范围，并明示节选，不扩展成全篇文件工程。
- 全文请求：用户明确要全文/整篇中英对照时，才使用完整 `nature-reader` 流程（若宿主可用），保持全文覆盖、来源映射及缺漏登记；依赖不可用时明确报告，不拿摘要替代全文。
- 本指南的忠实性优先于语言美化、反防御性写作和贡献压缩。不能把来源中的不利结果、适用限制或不确定性当成待删的防御性语言。讨论新证据也不能覆盖作者已确认的论文原文，除非用户要求修改。

## 先确定读到的是什么

1. 核对文献身份与版本：题名、作者/年份、可得DOI或出版链接、本地文件/附件及实际版本。预印本、录用稿、正式发表版和翻译附件不能混称；同题名不保证文本和图号相同。
2. 记录可复查的位置：PDF实际页序与印刷页码分开；有章节、段落、图表行或自建块ID时分别标明。HTML可用小节及原句定位。未得到页码或原段落时，写“用户提供片段，无页码”或“仅见摘要”，不得造位置。
3. 读取范围与支撑等级分开：读取了正文相关段落不等于读过整篇；下载成功、Zotero记录或搜索摘要不等于相关正文已核对。摘要可以忠实翻译，但不能借摘要补出具体试验、破坏机理或设计公式。
4. 原文转引他人结论时，说明是谁引用谁。未读被转引文献，不把二手陈述冒充直接核查的原始研究。

优先使用原文PDF或出版HTML；Zotero索引、OCR、机器译稿先走 [PDF与全文核对](pdf-extraction-and-fulltext-qc.md)。只有翻译附件时可解释该附件，但原始论断仍标“未核原文”，不能升级为全文证据。

## 一个证据单元保留四层

| 层次 | 内容 | 禁止混淆 |
|---|---|---|
| 原文依据 | 来源身份、实际读取范围、定位，以及必要短原句或原段落锚点 | 检索标题不能当原文；自己写的英文不能冒充引文 |
| 忠实译文 | 与所示片段对应的译文，保留其全部关键科学含义 | 摘要、压缩或解释不能标成完整译文；省略须标明且不得移除决定句意的条件 |
| 解释/推论 | 用清楚的中文说明作者结果；自己的力学解释或综合判断单独标识 | 不把自己的因果链、量化结果或跨研究综合放进译文 |
| 对本文的用途 | 可支持哪个写作论点、条件是否匹配，以及不支持什么 | 外部研究不替代用户结果；相似研究不等于可直接作设计依据 |

短问题可以用几句话完成这些区分，不必机械输出四个大标题。仅摘要、用户片段或不完整页面也能作范围内说明，但必须附相应状态。正式/多文献讨论宜留最小证据记录：`source/version + locator + original_span + translation + interpretation + claim_support + access/coverage + unresolved_items`。已有来源映射则复用，别伪造原文自带的块号。

引文遵守来源的引用与版权限制；聊天展示必要短句，长篇原文/双语稿只对用户提供或合法可处理的来源按授权范围生成。无法展示整段时，可给精确定位、短引句和标明范围的译述，不伪称已经逐字展示全文。

## 翻译时不可漂移的含义

- 主体与对象：哪个作者、试件、模型或组别得到哪个结果；内外叶板、拉结件类型、材料、几何、加载和边界条件不能换位或省略成泛化对象。
- 否定与量词：`not`、`no evidence`、`only`、`all`、`some`、`at least`、`up to`、`respectively`；没有证据证明不等于已证明不存在，最多/可达不等于平均或下限。
- 判断强度：可能、提示、与……一致、推测、已经证明分别保持。相关、SHAP贡献或敏感性不能译成独立因果证明；更低数值不能译成统计显著或全面领先。
- 数学信息：数值、正负号、范围端点、不等式、百分比与百分点、单位、公式、上下标、置信区间、图表号、引用及各自的对象映射。必要单位换算要另列原值和计算，不静默替换。
- 方法细节：简化假设、试件排除条件、数据划分、模型理想化和未覆盖的破坏模式，不改写成作者已经实施过的验证或筛选步骤。
- 土木术语：区分刚度/承载力、峰值荷载/应力、归一化组合度/绝对结构响应、弹性阶段/极限状态。先沿用作者及当前论文的术语台账；译名不确定时保留原词并提示，不为行文多样性轮换技术名称。

句式可调整，但不能在译文中填补缺失的研究结果。中文显化逻辑只限上下文已经支持的关系；不清楚时提出歧义，不为衔接补因果。忠实翻译与投稿润色式重写分开交付，后者只有用户授权才执行。

## 图表、公式与提取异常

- 依赖图表判断趋势时核对实际图表、坐标轴、图例、图注和对应文本；解释某行数值时定位该行及表注。没看到图时，只能说明“作者在文字中报告……”，不能声称已由图独立验证。
- 对公式、负号、小数点、上下标、OCR不确定的否定词等，优先查看原页面/区域。不确定处标记“原文/提取不清，待核”，停止以该片段支撑相应论断，不猜一个最符合论文预期的读法。
- 原文自身数值、单位或图表与正文不一致时，分别报告各处内容并保留分歧，不静默选一个或以译文修正原始文献。
- 无法取得全文、图表、清晰扫描或工具权限时，缩小回答范围或请求相应材料；不得以别篇文献的内容、模型常识或已有机器译稿补洞。

## 从文献说明到正文证据

1. 先回答来源在其条件下实际说明了什么，再讨论对当前写作的意义。多来源有分歧时列明各自对象/条件，不人为合成一致结论。
2. 用 [支撑分级](citation/support-grading.md) 判断它支持目标句的哪一部分，同时报告实际阅读范围。局部原段落能直接支撑某句，不代表整篇读完或本文工程条件已验证。
3. 将原文的结果、作者提出的解释、自己的推测及需要额外核查的工程应用分开。确有支撑时可给范围明确的正文建议；没有时不加引用装饰结论。
4. 交付前对照原文检查否定/量词、强度、数值映射、条件、关键术语及源译覆盖。检查脚本或反向翻译只能辅助，不能证明语义准确；只报告实际完成的核查。

## 来源与迁移边界

本指南最初以本机 `nature-reader` 2.0.0 的 core principles、workflow、grounding rules 和 output spec 为参考；本轮另核对上游固定版本的 grounding rules 与 equation handling，记录在[系统整合映射](../meta/systematic-integration-map.md)。归纳来源锚点、保守翻译、图表证据和缺漏登记；早期本地指纹保留在[迁移台账](../meta/external-skill-sources.md)。不复制上游代码、整篇输出模板、全文默认交付或强制图表裁剪。核心约束在未安装 `nature-reader` 的宿主也可执行；仅完整阅读稿的可选协作需要该独立skill及其依赖。
